1) Server Requirements
--------------------------------------------------------------------------------
- OS: Linux (Ubuntu 22.04+ or equivalent).
- Node.js: >= 22.5 (required for the built-in node:sqlite). 22.x LTS recommended.
- nginx: >= 1.20 (reverse proxy + TLS).
- PM2: Node process manager.
- Disk: >= 2 GB for the app + room for the database and uploaded images.
- Permissions: a non-root user (e.g. deploy) with sudo for installs/nginx.
- DNS: point 4 domains/subdomains at the server (example):
      rafidain.example          -> customer app
      agent.rafidain.example    -> agent panel
      admin.rafidain.example    -> admin panel
      provider.rafidain.example -> provider panel
- TLS certificate: Let's Encrypt (certbot) for all domains.

--------------------------------------------------------------------------------
2) Prepare the Code on the Server
--------------------------------------------------------------------------------
# Go to the apps directory
sudo mkdir -p /var/www/rafidain
cd /var/www/rafidain
git clone <repository-url> .
# or upload the full project folder via rsync/scp

# Confirm Node version (nvm recommended)
node -v        # must be >= 22.5
cat .nvmrc     # contains 22

--------------------------------------------------------------------------------
3) Install Server Dependencies (important: tsx is now a dependency)
--------------------------------------------------------------------------------
cd /var/www/rafidain/server
npm install            # installs ALL deps (including tsx needed to run prod)
# For strict production use: npm ci   (package-lock.json is now in sync)

--------------------------------------------------------------------------------
4) Configure Environment Variables (mandatory for production)
--------------------------------------------------------------------------------
cp .env.example .env
nano .env     # set at least the following:

  # Required — their absence blocks startup (fail-closed)
  JWT_SECRET=a-long-random-string-at-least-32-bytes
  TOTP_ENC_KEY=a-32-byte-hex-or-base64-encryption-key

  NODE_ENV=production
  PORT=4001
  DB_PATH=/var/www/rafidain/server/data/app.db

  CORS_ORIGINS=https://rafidain.example,https://admin.rafidain.example,https://agent.rafidain.example,https://provider.rafidain.example

  TRUST_PROXY=1
  COOKIE_SECURE=1
  CLUSTER_WORKERS=0            # 0 = auto by core count (with PM2 instances=1)
  SEED_ALLOW=0                 # do not auto-seed in production

  # Optional but recommended
  VAPID_SUBJECT=mailto:support@rafidain.iq
  # VAPID keys are auto-generated if left empty

# Generate a strong JWT_SECRET, e.g.:
#   node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
# Generate TOTP_ENC_KEY, e.g.:
#   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

--------------------------------------------------------------------------------
5) Database (migrations also run automatically on boot)
--------------------------------------------------------------------------------
cd /var/www/rafidain/server
npm run migrate        # creates/applies migrations (also auto-runs on start)

# Seed initial data (one time only — demo accounts):
#   npm run seed
# or enable self-seed on boot by setting SEED_ALLOW=1 (trial only).

--------------------------------------------------------------------------------
6) Run the Server (PM2)
--------------------------------------------------------------------------------
cd /var/www/rafidain
pm2 start deploy/ecosystem.config.js --env production
pm2 save
pm2 startup            # for auto-restart on server boot (follow its instructions)

# Verify healthy boot:
curl -s http://localhost:4001/api/health      # should return {"status":"ok",...}

# Server logs:
pm2 logs rafidain-server

--------------------------------------------------------------------------------
7) Build the Four Frontends and Deploy
--------------------------------------------------------------------------------
cd /var/www/rafidain
npm run build          # builds: customer-mobile, agent-panel, provider-panel, admin-panel
# (the build includes @rafidain/shared source automatically within the monorepo)

# Upload the dist folders to nginx paths:
sudo mkdir -p /var/www/rafidain/customer-mobile /var/www/rafidain/agent-panel \
             /var/www/rafidain/admin-panel /var/www/rafidain/provider-panel
rsync -a customer-mobile/dist/ /var/www/rafidain/customer-mobile/
rsync -a agent-panel/dist/    /var/www/rafidain/agent-panel/
rsync -a provider-panel/dist/ /var/www/rafidain/provider-panel/
rsync -a admin-panel/dist/    /var/www/rafidain/admin-panel/

--------------------------------------------------------------------------------
8) Configure nginx (Reverse Proxy + HTTPS)
--------------------------------------------------------------------------------
# Copy the config files into a dedicated folder:
sudo mkdir -p /etc/nginx/rafidain
sudo cp deploy/nginx.headers.conf /etc/nginx/rafidain/
sudo cp deploy/nginx.static.conf /etc/nginx/rafidain/
sudo cp deploy/nginx.api.conf    /etc/nginx/rafidain/

# Edit and enable nginx.conf.example:
sudo cp deploy/nginx.conf.example /etc/nginx/sites-available/rafidain
sudo ln -s /etc/nginx/sites-available/rafidain /etc/nginx/sites-enabled/rafidain
# adjust domain names/paths inside to match your server if needed.

# Let's Encrypt certificates:
sudo apt-get install certbot python3-certbot-nginx -y
sudo certbot --nginx -d rafidain.example -d www.rafidain.example \
                   -d agent.rafidain.example -d admin.rafidain.example \
                   -d provider.rafidain.example

# Test and reload:
sudo nginx -t
sudo systemctl reload nginx

--------------------------------------------------------------------------------
9) Persistent Storage & Backups
--------------------------------------------------------------------------------
- Ensure these folders are on persistent storage and included in backups:
      /var/www/rafidain/server/data/      (SQLite DB + WAL)
      /var/www/rafidain/server/uploads/   (uploaded images)
- The system provides backups via:
      cd /var/www/rafidain/server && npm run restore
  and supports offsite upload (GCS/offsite) via .env variables.
- Schedule a periodic (cron) backup of the two folders above.

--------------------------------------------------------------------------------
10) Daily Operations Commands
--------------------------------------------------------------------------------
pm2 status                 # process status
pm2 logs rafidain-server   # logs
pm2 restart rafidain-server
pm2 reload rafidain-server # zero-downtime reload
sudo systemctl reload nginx

11) Troubleshooting & Blockers Fixed Before Install
--------------------------------------------------------------------------------
- [FIXED] npm start failed with --omit=dev because tsx was a devDependency.

- [FIXED] Production nginx files contained hard-coded Windows paths
    (D:/1h1h/deploy/...). Fix: changed to relative include
    `include nginx.headers.conf;` (resolves relative to the file's folder,
    so it works on both Linux and Windows).
    Note: deploy/nginx.local.conf keeps Windows paths on purpose for local dev.

- [FIXED] Missing limit_req_zone in nginx.conf.example (would block nginx
    startup). Fix: added the zone at the top of the file.

- [EXISTING] SQLite is already hardened via WAL + busy_timeout +
    synchronous=NORMAL in server/src/db/worker.ts — no action needed.

- [EXISTING] /api/health endpoint is ready for load-balancer health checks.

Common symptoms & cures:
  - EADDRINUSE on boot: port 4001 is taken by a previous process => kill it
    and restart.
  - 401 on protected routes: ensure the session/CSRF cookie is sent and that
    NODE_ENV=production with COOKIE_SECURE=1 and HTTPS enabled.
  - Identity-doc images return 404: intended behavior (sensitive files are
    never served publicly).

--------------------------------------------------------------------------------
12) Security & Scaling Notes
--------------------------------------------------------------------------------
- Never commit the .env file (it is gitignored).
- Enable a firewall (ufw) and allow only 22/80/443.
- For heavy horizontal load: migrate from SQLite to PostgreSQL.
- Security headers (HSTS, CSP, X-Frame-Options, ...) are set in
  nginx.headers.conf; review the CSP (script-src 'self') before production if
  the frontends use inline scripts.
- There is no automated deploy pipeline (CD) yet; deployment is manual as in
  this guide.
