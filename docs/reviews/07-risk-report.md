# تقرير المخاطر

> التاريخ: 2026-08-09 — الحالة: ✅ **جاهز للإطلاق** — لا مخاطر حرجة مفتوحة؛ المخاطر المتبقية مُخفَّفة ومؤجلة بوعي

## 1. منهجية التصنيف

- **الأثر:** عالٍ/متوسط/منخفض على العمل (مالياً، تشغيلياً، قانونياً، أو تجربة مستخدم).
- **الاحتمال:** عالٍ/متوسط/منخفض.
- **الدرجة:** حرجة = أثر عالٍ × احتمال ≥ متوسط؛ عالية = أثر عالٍ × احتمال منخفض، أو أثر متوسط × احتمال عالٍ؛ متوسطة؛ منخفضة.

## 3. المخاطر غير المقبولة (يُعالج قبل الإنتاج الفعلي الواسع)

1. **R2/R5 — دورة الدفع اليدوية:** قبل التوسّع، إما توثيق صارم لعملية التحقق من اللقطات (تدريب/نقل صلاحيات) أو تكامل بوابة دفع إلكترونية.
2. **R6/R13 — الحفظ:** نقل النسخ الاحتياطية إلى تخزين خارجي (ملف/سحاب) بحيث يتحمّل فشل القرص المحلي.
3. **R3 — نقل التوكن إلى HttpOnly cookie** عند توفّر البنية.

## 4. المخاطر المقبولة/المؤجلة (موثّقة في `system-analysis.md`)

- R1 (قيد معماري مقصود)؛ R4 (Redis عند التوسع)؛ R8 (قرار منتج)؛ R10 (طبيعة Web Push).

## 5. مؤشرات الإنذار المبكر (KPIs)

| المؤشر | العتبة | الإجراء |
|---|---|---|
| زمن استجابة `GET /api/orders` عند الذروة | > 500ms | فحص S1/الفهارس/الترقيم |
| خطأ `SQLITE_BUSY` محوّل إلى 503 | > 0.5% | Worker Thread أو Postgres |
| رصيد غير متطابق مع دفتر `balance_after` | أي اختلاف | إيقاف القبول فوراً والتحقق |
| طلبات شحن معلّقة بلا قرار | > 48 ساعة | تذكير/تحويل للمسؤولين |
| عدد طلبات من عميل واحد في الدقيقة | > حد النطاق | مراجعة حد المعدل |

## 6. الخلاصة

الملف جاهز للإطلاق بمخاطر مقبولة ومخففة. البنود الثلاثة في القسم 3 يجب أن تُغلق قبل التوسّع الواسع (الدفع اليدوي، النسخ خارج الموقع، HttpOnly cookie). باقي المخاطر مدرَجة ومراقَبة عبر مؤشرات الإنذار أعلاه.
