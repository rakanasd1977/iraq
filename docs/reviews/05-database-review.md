# تقرير مراجعة قاعدة البيانات

> التاريخ: 2026-08-09 — الحالة: ✅ **معتمدة** — مخطط متسق، مهاجرة بأثر رجعي، نسخ احتياطي آلي

## 1. نظرة عامة

- **المحرك:** SQLite عبر `node:sqlite` الأصلي (`DatabaseSync`) — ملف `server/data/app.db`، وضع WAL، `foreign_keys=ON`، `busy_timeout` مع إعادة محاولة تلقائية (3 محاولات).
- **المخطط:** مُدار بالكامل عبر سجل هجرات تراكمي (23 هجرة 001–023) في `db/migrate.js` مع جدول `schema_migrations` وتطبيق ذري لكل هجرة.

## 3. السلامة المالية

| الجانب | الحالة |
|---|---|
| دفتر الحركات | كل حركة محفظة تحمل `balance_after` — الرصيد قابل لإعادة البناء والتدقيق الكامل |
| الذرّية | خصم/رد العمولة والتحقق من الرصيد داخل `transaction()` واحد |
| منع البيع المزدوج | فحص تداخل `check_in/check_out` للغرف داخل المعاملة + حد المقاعد/المخزون |
| تثبيت المبالغ | قرار موثّق: الأعمدة `REAL` مع `round2` في كل الكتابات (لا فائدة من إعادة بناء الجداول إلى INTEGER) |
| القيود | CHECK/UNIQUE على التقييمات، نسب 0–100، قيود مالية إيجابية |
| الأرقام المرجعية | `ORD-YYYY-xxxxxx` فريد مع إعادة محاولة عند التصادم (حتى 5)، و`RCH-` للشحن |

## 4. الأداء والفهارس

- فهارس تغطي: `orders(governorate_id,status)`، `orders(created_at)`، `bookings(order_id/provider_id/dates)`، `lease_payments(agent_id)`، `activity_log(user_id,created_at)`، `products(category_id/provider_id)`، `notifications(user_id,is_read,id DESC)`، و`idempotency_keys/sessions`.
- ترقيم إلزامي بسقف (50/100) يمنع جلب صفوف غير محدودة.
- N+1 معالجة (دفعات `IN` و`JOIN` في القوائم) — راجع تقرير الأداء §2.

## 5. التشغيل والحفظ

- **نسخ احتياطي آلي:** `VACUUM INTO` ذري كل ساعة إلى `data/backups/` مع `wal_checkpoint(TRUNCATE)`، وإبقاء آخر 7 نسخ — استعادة متسقة بلا قفل الكاتب.
- **تدوير:** `activity_log` (90 يوم) ومفاتيح Idempotency (7 أيام) عند الإقلاع وشهرياً.
- **أمان الملفات:** `server/data/` مستثنى من git؛ قاعدة الإنتاج لا تتسرب للمستودع.
- **اختبارات ببيئة معزولة:** كل الاختبارات تشغّل قاعدة مؤقتة — لا تمسّ قاعدة التشغيل.
